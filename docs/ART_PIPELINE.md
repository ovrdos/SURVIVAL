Rule 1
Do not create a new system if POSTAL already provides one.
Rule 2
Do not rewrite working POSTAL functionality just because it is old.
Rule 3
Prefer data/configuration changes over new C/C++ code where possible.
Rule 4
Graphics and animation are the primary modernization targets.
Rule 5
Keep the original isometric gameplay orientation.
Rule 6
Every new feature must identify the existing POSTAL mechanism it extends or reuses.
